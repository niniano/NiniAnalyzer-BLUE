# NiniAnalyzer Public 1.0.0-rc4.2 · 빌드 키트

RC4.1(Windows 실사용 검증 후보) + **선택형 기존 기록 죽척 재검사**. 새 폴더에 풀어서 `Build_Public_EXE.cmd`.
RC4.1에서 확인한 죽척 판정·첫 공격자 줄·폰트·스크롤 HF6는 그대로입니다.

## 새 기능: 설정 > 죽척 재검사 열기
| 단계 | 동작 |
|---|---|
| ① 후보 검색 | 저장된 원본 로그에서 죽척(5384)이 있는 트라이만 찾음. **읽기 전용**: 어떤 결과 파일도, 공용 스킬 이름 캐시도 쓰지 않음 |
| ② 목록 | 트라이별 죽척 횟수 · 현재 사망 · 재검사 후 예상 사망 · 재검사 가능 여부(원본 없음/손상이면 선택 불가). 사망 수 변화가 예상되는 트라이만 미리 체크 |
| ③ 선택한 Try 재검사 | 체크한 트라이만: 재분석 직전에 원본 로그를 **처음부터 끝까지** 엄격하게 읽기(UTF-8 오류·NUL 바이트·gzip 잘림이면 중단) → 반복 문제 집계 zip 백업 → 트라이 결과 zip 백업 → 재분석. 확인·백업 실패 시 그 트라이는 재분석 안 함 |
| ④ 결과 | **로그 사실**(뺀 사망 + 근거 시각·스킬 / 근거 없어 유지한 사망)과 **엔진 재판정**(사망 수·첫 사망자·화면 표시 원인·B31 원인·기믹 판정·첫 공격자 변경 전→후, "확정 아님")을 분리 표시 |
| 갱신 | 재분석 파이프라인이 그 트라이의 전멸 복기와 같은 보스의 반복 문제 집계를 함께 갱신 → 화면 목록 새로고침 |

진행 중에는 로그 가져오기·실시간 감시·저장 복기 최신화·프로그램 종료가 막힙니다(같은 폴더 동시 수정 방지).

## 같이 고친 기존 문제 (실제 데이터에서 발견)
- **반복 문제 집계가 다른 트라이 파일을 다시 쓰던 문제.** 새 트라이를 가져올 때마다 같은 보스의 이전 트라이 `raid_review.json`이 기믹 연결 단계 없이 다시 저장되어, 이전 트라이의 **기믹 판정(예: 유독한 물방울 미섭취)이 B31 판정(예: 배양된 파열)으로 바뀌어** 있었습니다. 시험 데이터의 Try 1~3이 이 상태였습니다. 이제 집계는 다른 트라이를 메모리에서만 읽습니다(트라이당 약 10ms).
  - 이미 바뀐 기존 트라이는 그대로입니다. 재검사한 트라이는 기믹 판정 연결이 복구됩니다(결과에 "화면 표시 원인" 변경으로 표시).
- **종료 시 Tk 예약 콜백 경고** (`invalid command name ..._pump_queue`): 창을 닫을 때 남은 예약 작업을 먼저 취소. 공개판 검사 60개 실행 중 경고 0회.

## 실제 PC 확인 순서
1. 폰트 없는 다른 Windows PC에서 설치 → 글꼴
2. 첫 실행 → 최근 세션 자동 열림, 트라이 화면 스크롤·휠, 제목 아래 첫 공격자 줄
3. 설정 → 죽척 재검사 → 후보 검색 (결과 변화 없음 확인) → 1개만 체크해 재검사 → 결과/백업 zip 확인
4. 냥꾼 죽척 실전 트라이: 다시 공격하면 사망 제외 / 죽척 직후 실제 사망은 유지
5. 창 전환·종료 시 오류창/경고 없음, 작업표시줄 아이콘 하나, 제거 후 기록 유지

- 공용 엔진 변경분: GOLD 기준 사본에 안전 패치 적용 후 전체 테스트 882개 통과 (이번 수정 후 다시 실행)
